# 実装依頼: 変化点検出のタイル分割diff化

## 背景

bunkatsu(動画/GIFから変化点フレームのみを静止画抽出するブラウザ内完結Webアプリ)の変化点検出は、現在フレーム全体の平均絶対差(diffPercent)で判定しており、画面の一部だけの変化が全体平均に薄められて検出できない(しきい値を下げると圧縮ノイズを誤検出する)。これを「タイル分割diff+ノイズフロア」方式に切り替え、局所的な変化を薄めずに捉えつつノイズ耐性を保つ。

## 対象

- リポジトリ: bunkatsu
- 作業ブランチ: plan/2026-07-25-tile-diff(ここから作成して作業する)
- ベースブランチ: plan/2026-07-23-initial-app(main ではない点に注意。初期実装がこのブランチにあり未マージのため、ここから作業ブランチを切る)

## タスク(この順で)

1. src/core/diff.ts: ノイズフロア付きタイル分割diff関数(例: tileDiffPercent(a, b): number — 命名は実装者裁量)を追加し、src/core/diff.test.ts に単体テストを追加する。計算手順:
   1. 2つの gray64(Uint8Array 長さ4096)の画素ごと絶対差を取り、ノイズフロア(絶対差が NOISE_FLOOR = 10 未満は 0 扱い。名前付き定数として実装し、後から変えやすい形にする)を適用する
   2. 64x64 グリッドを 8x8 のタイル(各タイル 8x8 セル = 64セル)に分割し、タイルごとに(フロア適用後の)平均絶対差を計算して 0〜100% に正規化する(0〜255 → 0〜100)
   3. 全64タイルのうち最大の差分率をフレームスコアとして返し、呼び出し側でしきい値と比較する
2. src/core/extractor.ts: extractChangedFrames 内の判定を diffPercent から新関数へ切り替え、src/core/extractor.test.ts を更新する。「直前に採用したフレームと比較」「先頭フレーム常時採用」ロジックは維持する。既存の diffPercent / toGray64 は変更しない(diffPercent が他から未使用になる場合も削除せず残してよい — 削除するかは実装者裁量、ただしテストは整合させる)
3. README.md のしきい値説明を更新する(しきい値の意味が「フレーム全体の平均変化率」から「最も変化したタイル(局所領域)の変化率」に変わることを反映)

補足:

- サンプリング解像度は 64x64 のまま変更しない
- UI は変更しない(スライダーの意味が「局所変化率」に変わるが UI 自体・設定項目・デフォルト値3%はそのまま)
- SSIM 等の高度な類似度指標は導入しない
- 検証動画による実測は検収時に采配役が行うため、実装スコープ外
