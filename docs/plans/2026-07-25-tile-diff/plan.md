# 変化点検出のタイル分割diff化 実装計画

- 日付: 2026-07-25
- ブランチ: plan/2026-07-25-tile-diff
- ベースブランチ: plan/2026-07-23-initial-app(初期実装が未マージのためここから作業ブランチを切る。main ではない)
- 実装担当(駒): Claude sonnet(変更範囲が diff.ts / extractor.ts / テスト / README に閉じており、設計は本計画で確定済みの標準的実装のため)

## 背景・目的

現行の変化点検出は「フレーム全体を64x64グレースケールに縮小し、全画素の平均絶対差(diffPercent)」で判定するため、画面の一部だけの変化(UI要素追加・小さな色変化)が全体平均に薄められて検出できない。しきい値を下げると動画圧縮ノイズを誤検出するトレードオフが実測で確認済み(デフォルト3%では1280x720中の40x30px色変化を見逃し、1%に下げるとノイズ誤検出)。局所的な変化を薄めずに捉え、かつノイズ耐性を保つことが目的。

## スコープ

### やること

- タイル分割diff: 64x64グリッドを 8x8 のタイル(各タイル 8x8 セル = 64セル)に分割し、タイルごとの差分率の最大値をフレームの差分スコアとする
- ノイズフロア: 画素ごとの絶対差が小さい(圧縮ノイズ由来の)ものを差分計算前に切り捨てるデッドバンドを導入(初期値: 絶対差10/255未満は0扱い。タイル化で上がるノイズ感度への対策)
- 単体テストの追加・更新(diff.test.ts / extractor.test.ts)
- README のしきい値説明の更新(しきい値の意味が「フレーム全体の平均変化率」から「最も変化したタイル(局所領域)の変化率」に変わることを反映)

### やらないこと

- SSIM等の高度な類似度指標(タイル+デッドバンドで足りるかをまず見る)
- サンプリング解像度の変更(64x64は維持)
- UI変更(スライダーの意味が「局所変化率」に変わるがUI自体・設定項目・デフォルト値3%はそのまま)
- 検証動画による実測(これは検収時に采配役が実施する。実装駒のスコープ外)

## 方針

src/core/diff.ts に新しい差分関数(例: tileDiffPercent(a, b): number — 命名は実装者裁量)を追加し、src/core/extractor.ts の extractChangedFrames 内の判定を diffPercent からそれに切り替える。計算手順:

1. 2つの gray64(Uint8Array 長さ4096)の画素ごと絶対差を取り、ノイズフロア(絶対差が NOISE_FLOOR = 10 未満は 0 扱い)を適用する
2. 64x64 グリッドを 8x8 のタイル(各タイル 8x8 セル)に分割し、タイルごとに(フロア適用後の)平均絶対差を計算して 0〜100% に正規化する(0〜255 → 0〜100)
3. 全64タイルのうち最大の差分率をフレームスコアとして返し、呼び出し側でしきい値と比較する

既存の diffPercent / toGray64 は変更しない(diffPercent が他から未使用になる場合も削除せず残してよい — 削除するかは実装者裁量、ただしテストは整合させる)。extractChangedFrames の「直前に採用したフレームと比較」「先頭フレーム常時採用」ロジックは維持する。videoSource.ts / gifSource.ts / UI は変更しない。

代替案として全体平均+局所の2段しきい値も考えたが、UIが複雑になるため単一スコア(max tile)に集約する方式を採る。

設計根拠(概算): 前回見逃した「1280x720中の40x30px色変化」は 64x64 上で約 2x3 セルの大きな輝度差になり、該当タイル(64セル)内で 5〜6 セルが大きく変化すると該当タイルの差分率は 3〜4% となり、デフォルトしきい値 3% で拾える見込み。圧縮ノイズは画素あたりの差が小さいためノイズフロアでほぼ 0 になる。
