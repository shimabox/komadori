## 背景・目的

動画や GIF から静止画を切り出すとき、全フレーム保存では枚数が膨大で冗長になる。フレーム間の「変化点」だけを検出して静止画として抽出・ダウンロードできる Web アプリを作る。主用途は画面録画・デモ動画からの手順書/スライド起こし。ファイルはサーバーに送らず、すべてブラウザ内で処理する(プライバシー安全・静的ホスティング可能)。

## スコープ

### やること

- 動画(ブラウザが再生できる形式: mp4/webm 等)/ GIF の読み込み(ファイル選択 + ドラッグ&ドロップ)
- フレームサンプリングと変化点検出(感度しきい値スライダーで調整 → 再デコードなしで再抽出)
- 抽出フレームのサムネイル一覧表示(フレームごとに採用/除外の手動切り替え)
- PNG 個別ダウンロード / 選択フレームの ZIP 一括ダウンロード
- 検出ロジックのユニットテスト(Vitest)、ESLint + Prettier 整備
- README(使い方・開発コマンド)
- UI は日本語

### やらないこと

- サーバーサイド処理・アカウント・データ永続化(すべてブラウザ内で完結)
- 動画編集機能(トリミング等)
- デプロイ整備(GitHub Pages 等)— 今回はローカル動作(`npm run dev` / `npm run build`)まで
- i18n(日本語のみ)

## 方針

完全クライアントサイドの静的 Web アプリとして実現する。Vite + TypeScript(Vanilla、UI フレームワークなし)+ Vitest を採用し、ランタイム依存は gifuct-js(GIF デコード)と fflate(ZIP 生成)の 2 つのみに絞る。

選ばなかった代替案:

- WebCodecs — Safari 対応と demux の複雑さから不採用
- ffmpeg.wasm — 数十 MB のバイナリで過剰なため不採用
- サーバーサイド処理 — 運用コストとプライバシーの点で不採用

### モジュール構成

```
src/
  main.ts              — エントリポイント。UI と core の配線
  ui/                  — DOM 構築・イベント(入力エリア、設定パネル、進捗、結果一覧)
  core/
    types.ts           — SampledFrame 等の型定義
    frameSource.ts     — フレーム供給の共通インターフェース
    videoSource.ts     — <video> + seek + canvas で動画からフレーム列を生成
    gifSource.ts       — gifuct-js で GIF をデコードしフレーム列を生成
    diff.ts            — 縮小グレースケール化とフレーム間差分率の計算(純関数)
    extractor.ts       — 差分系列としきい値から採用フレームを決定・再抽出(純ロジック)
    zip.ts             — 採用フレームの PNG 化と ZIP 生成(fflate)
```

### FrameSource インターフェース(メモリ設計の核)

スキャン時にフル解像度は保持しない。各サンプルフレームにつき (a) 64×64 グレースケール `Uint8Array`(差分計算用)と (b) 表示用サムネイル JPEG Blob(幅 320〜400px 程度)のみ保持する。フル解像度 PNG はダウンロード時に必要なフレームだけ元ソースから再取得する。

```ts
interface FrameSource {
  /** サンプリングしながらフレームを順に供給(進捗コールバック・中断シグナル付き) */
  scan(opts: ScanOptions): AsyncGenerator<SampledFrame>;
  /** 指定フレームのフル解像度 PNG を再取得(動画: 該当時刻へ再 seek / GIF: 再デコード・合成) */
  renderFull(frame: SampledFrame): Promise<Blob>;
  /** objectURL 等の後始末 */
  dispose(): void;
}
// SampledFrame: { index, timestampMs, gray64: Uint8Array, thumbnail: Blob, width, height }
```

### フレーム取得(動画)

`<video muted playsinline preload="auto">` に objectURL を読み込み、`currentTime` を進めて `seeked` イベント後に canvas へ drawImage。サンプリング間隔は既定 200ms、総サンプル数が上限 600 を超える長さの動画では間隔を自動で広げる。間隔は設定 UI から手動変更も可。`requestVideoFrameCallback` は使わない(seek 方式で互換性優先)。

### フレーム取得(GIF)

gifuct-js で全フレームデコードし、ディスポーザル処理を適用して各フレームを合成。フレーム遅延から累積タイムスタンプを計算。GIF は間引きなしで全フレーム対象(ただしサンプル上限 600 は適用)。

### 変化点検出

各フレームを 64×64 に縮小しグレースケール化 → 「直前の採用フレーム」との平均絶対差(0〜255)を 0〜100% に正規化した差分率を計算 → しきい値(既定 3%、画面録画の離散的な画面切替向け)以上なら採用。先頭フレームは常に採用。「直前サンプルとの比較」ではなく「直前の採用フレームとの比較」にする(ゆっくり進む累積変化も拾うため)。しきい値変更時は保持済み gray64 列に対して逐次再評価するだけなので、再デコードなしで即時再抽出できる(extractor.ts の純ロジック、Vitest 対象)。

### UI(1画面)

ファイル入力(D&D + クリック選択)/ 設定(しきい値スライダー 0.5〜30%・既定 3%、サンプリング間隔)/ スキャン進捗バー + キャンセルボタン / 結果一覧(サムネイルグリッド、タイムスタンプ表示、チェックボックスで採用/除外、個別ダウンロードボタン)/ ZIP 一括ダウンロードボタン。しきい値変更時、手動の採用/除外操作はリセットして自動判定に戻す。非対応形式・デコード失敗はエラーメッセージ表示。500MB 超のファイルは警告表示(処理は継続可)。

### 出力

PNG はフル解像度。ファイル名 `0001_00m03s200.png` 形式(連番 + タイムスタンプ)。ZIP 名は `<元ファイル名>_frames.zip`。fflate は非同期 API を使う。

### 開発環境

Node v20.19.5 / npm。npm scripts: `dev` / `build` / `preview` / `test`(Vitest)/ `lint`(ESLint)/ `format`(Prettier)。gifuct-js に型定義がなければ自前 d.ts(`declare module`)で対応。
